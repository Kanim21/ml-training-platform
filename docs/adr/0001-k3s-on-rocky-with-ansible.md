# ADR 0001: K3s on Rocky Linux, provisioned with Ansible

**Status:** Accepted

## Context

The platform needs a real multi-node Kubernetes cluster so node loss can be
simulated (drill 1) and the full cluster can be rebuilt from the repo
(drill 6). It has to be cheap to run and rebuild. It should also show Linux
and bare-metal-style operations, not just a managed control plane.

## Decision

- **K3s**, 1 server and 2 agents. It's a single binary, has a small
  footprint, and is still conformant Kubernetes. Embedded SQLite on one
  server is enough because control-plane HA is out of scope. Drills target
  agent nodes.
- **Rocky Linux 9/10** with SELinux enforcing and firewalld on. These are
  RHEL-compatible and match what many enterprises run. K3s runs with
  `selinux: true` and the `k3s-selinux` policy, so neither SELinux nor
  firewalld gets disabled to make things work.
- **Ansible** for OS hardening and the K3s install. It's agentless and
  idempotent, so re-running it is safe. The K3s version and the install
  script's SHA-256 are pinned in `group_vars/all.yml`.
- The join token is generated by K3s on the server, read during the play and
  passed to agents in memory. It never touches the repo.
- VM creation stays out of scope for Ansible (see `docs/vms.md`).

## Consequences

- Single server means a server failure takes the API down. That's accepted:
  drill 6 covers it as a full rebuild.
- EKS (with Karpenter and real spot) is left to optional phase 6.
